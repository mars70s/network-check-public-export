# Test Specification

## 文書の目的

この文書は、Network Checkの公開機能を公開前に確認するための受け入れ確認仕様です。公開されているDNS、TLS、HTTP、メール関連レコードなどをread-onlyで確認し、結果表示、安全境界、データ保存方針が公開文書の説明と矛盾しないことを確認します。

この文書は、脆弱性診断手順や侵入試験手順を定めるものではありません。攻撃手順や具体的な回避方法ではなく、公開サービスとして期待される品質と安全境界の確認観点を整理します。

## 公開リポジトリにおけるテスト対象範囲

対象範囲は、公開リポジトリに含まれる通常の利用者向け機能と公開説明ページです。

- Client Informationの表示
- Domain、DNS Timing、IPv4 / IPv6 Preference
- TLS、HTTP/2、Security Headers
- MX、SPF、DMARC
- PTR、CAA
- Domain Multi Check
- 公開説明ページ、privacy、terms、contact
- 入力値エラー時の表示
- 公開向けの接続先検証
- 匿名利用集計として保存する情報の範囲

## 対象外範囲

次の項目は、この公開用テスト仕様の対象外です。

- ソースコードやテストコードの内部設計レビュー
- デプロイ、サーバ、DNS、Nginx、systemdなどの運用設定
- 実行環境名、内部URL、内部運用手順
- 秘密情報、認証情報、鍵、ログ、databaseなどのruntime data
- 不正利用対応の詳細や運用しきい値
- 脆弱性スキャン、侵入試験、認証試行、負荷試験

## 公開機能ごとの確認観点

### DNS確認

Domain、DNS Timing、IPv4 / IPv6 Preference、PTR、CAAでは、入力に応じた公開DNS情報が表示されることを確認します。

- 有効なdomainまたはIPアドレスに対して、期待される種類のDNS結果が表示される。
- recordが存在しない場合や問い合わせに失敗した場合に、利用者が状態を理解できる表示になる。
- DNS問い合わせ時間は参考値として表示され、性能全体を保証する表現になっていない。
- 対象側の設定変更やportへの接続を行う説明になっていない。

### HTTP確認

TLS、HTTP/2、Security Headersでは、公開HTTP / HTTPS対象に対する通常の確認結果が表示されることを確認します。

- TLSでは、標準ポート443への通常接続で取得できるTLS version、cipher、certificate情報が表示される。
- HTTP/2では、HTTP versionとHTTP statusが表示される。
- HTTP/2確認はredirectを自動追跡せず、crawlや性能測定を行う説明になっていない。
- Security Headersでは、選択したresponse headerの有無と値が表示される。
- headerの有無だけでWeb site全体の安全性を保証する表現になっていない。

### MX / SPF / DMARCなどメール関連レコード確認

MX、SPF、DMARCでは、公開DNSに登録されているメール関連情報の表示を確認します。

- MX recordの有無と値が表示される。
- SPFとDMARCの公開DNS recordが表示される。
- recordがない場合に、診断対象ごとの結果として分かりやすく表示される。
- SMTP接続、認証試行、メール送信、実際のメール認証を行う説明になっていない。

### Domain Multi Check

Domain Multi Checkでは、domainを入力にする複数の確認項目をまとめて実行できることを確認します。

- 選択した確認項目だけが実行対象になる。
- 各結果に個別機能と同じ入力境界と限界が適用される。
- PTRやSecurity Headersなど、入力形式が異なる機能がDomain Multi Checkに含まれないことが説明と一致する。
- 一部の確認が失敗しても、他の確認結果が読み取れる表示になる。

### 入力値エラー時の表示

入力値が不足している場合、形式が不正な場合、公開確認対象として扱えない場合の表示を確認します。

- 利用者が修正すべき入力内容を理解できる。
- 内部例外、stack trace、内部パス、秘密情報が表示されない。
- domain、IPアドレス、URLの入力形式ごとの境界が公開文書と一致する。
- エラー表示が過度に攻撃手法へ寄った説明になっていない。

### 安全な接続先検証

外部ネットワーク確認の前に、公開確認対象として扱える接続先かを検証することを確認します。

- ループバック、プライベート、リンクローカル、マルチキャスト、予約済み、その他の非公開または通常の公開確認対象として扱うべきではない接続先を拒否、または回避する。
- embedded credentialsを含むURLや、許可されていないportを受け付けない。
- redirectによって検証済みの接続先境界が変わる可能性がある確認処理では、redirect追跡を制限する。
- 確認観点は一般的な安全境界にとどめ、具体的な突破手法や攻撃ペイロード集を文書化しない。

### データ保存方針

Data Handlingの説明と実際の保存方針が矛盾しないことを確認します。

- 通常の診断結果はrequestごとに生成され、入力対象ごとの診断履歴として保存しない。
- 匿名利用集計は、日ごとの利用回数や選択項目の件数把握を目的とする。
- 利用者が入力したdomain、IPアドレス、URLを匿名利用集計recordの保存対象にしない。
- HTTP headers、cookies、session、request body、秘密情報、認証情報、認可ヘッダー、個別の診断結果を匿名利用集計recordへ保存しない。

## 受け入れ条件

公開前の受け入れ条件は次のとおりです。

- 公開機能の主要な正常系結果が、READMEとChecksの説明に沿って表示される。
- 入力値エラー時に、利用者向けの自然なエラー表示になる。
- 公開確認対象として扱うべきではない接続先が拒否、または回避される。
- 結果表示が対象全体の安全性や正常性を保証する表現になっていない。
- 内部運用情報、秘密情報、runtime data、ログが公開画面や公開文書に含まれない。
- データ保存方針がData Handlingの説明と矛盾しない。

## 公開前確認チェックリスト

- README、Security Policy、Data Handling、Checksの説明と公開画面の表示が矛盾していない。
- 新規または変更した公開文書に、内部運用情報や秘密情報が含まれていない。
- Markdownに未閉じのcode fence、HTMLコメント、HTMLタグ、Jinjaブロック、conflict markerがない。
- 公開機能の入力、正常結果、エラー表示、安全境界が確認されている。
- runtime、server、deploy、source codeの変更を含まない文書変更である。

## セキュリティ境界確認

Network Checkは、公開されている通常のネットワーク情報を確認するためのread-onlyサービスです。受け入れ確認では、次の境界を維持していることを確認します。

- 対象システムの設定、data、稼働状態を変更しない。
- port scan、脆弱性診断、侵入試験、認証情報の試行、メール送信、大規模なcrawlを行わない。
- public HTTP / HTTPS URL以外や、公開確認対象として扱うべきではない接続先を受け付けない。
- redirect追跡を制限し、利用者が指定した公開対象とは異なるネットワーク位置へ到達しないようにする。
- 公開文書では一般的な安全境界を説明し、内部運用の詳細を公開しない。
